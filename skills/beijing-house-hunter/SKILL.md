# 北京找房（beijing-house-hunter）

## 核心工作流（五步，顺序固定，不得改动）

```
条件解析 → 渠道装载 → 并行搜索 → 验证层 → 统一输出
```

### 第 1 步：条件解析（可配置）

从用户请求中解析出标准条件 schema，缺省字段按下表默认值，解析后**复述给用户确认**再执行：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `budget_max` | 必填 | 预算上限（万元） |
| `tax_inclusive` | `true` | 默认按含税总支出比较（见 references/tax-calculator.md）；设 false 则比裸价 |
| `rooms` | 两居或三居 | 目标户型 |
| `area_min` / `area_max` | 70 / 100 ㎡ | 面积区间 |
| `districts` | 不限 | 区域/板块（如：丰台、大兴、南四环外五环内） |
| `house_types` | 不限 | 定向安置房 / 商品房次新 / 新房现房 / 回迁转商 |
| `age_max` | 不限 | **房龄上限（年）**。房龄 = 当前年份 − 建成年份（例：2020年建成，2026年房龄6年）；`age_max=6` 即只看建成年份 ≥ 2026−6=2020 的房子（含当年）。多期小区按楼栋批次核对，不能只用小区区间 |
| `year_min` | 不限 | 建成年下限（与 `age_max` 等价，二选一配置；"次新"= 2015+ 即 age_max ≈ 11） |
| `commute_anchor` | `null`（忽略通勤） | 若给定（如"8号线和义站"），仅标注每个候选的通勤方式，**不得作为筛除条件，除非用户明说** |
| `payment` | 全款 | 全款 / 贷款（影响议价策略与渠道选择） |

**产权硬排除项（默认全部排除，用户明说才开放）**：
- 三定三限房未满 5 年（按房本/契税票起算）
- 无房本 / 小产权 / 协议房
- 保障性租赁住房混挂
- 共有产权房（申购人有住房转出记录即永久禁申——换房家庭默认排除）

### 第 2 步：渠道装载（对扩展开放，对修改关闭）

用 Glob/Bash 列出本 skill `channels/` 目录下**全部** `.md` 文件，按文件名编号顺序全部读取并执行。每个渠道模块自带：适用条件、搜索方法模板、证据标准。

**扩展规则（铁律）**：
- 新增渠道 = 在 `channels/` 放一个新编号的 `.md` 文件（如 `07-douyin.md`）
- **禁止**为接入新渠道而修改 SKILL.md 或任何已有渠道文件
- 渠道文件头部标注 `enabled: false` 的默认跳过，用户点名才启用

### 第 3 步：并行搜索

各渠道独立产出候选清单（小区、房源、价格、URL）。可派 subagent 并行，但**subagent 产出只算线索，不算证据**。

### 第 4 步：验证层（结果进最终表的前置闸门）

1. **房源级证据**：最终表每一行必须有具体房源（小区+面积+户型+挂牌价+来源URL）。只有小区均价、没有具体房源的，进"待核实"区。
2. **数据黑名单过滤**：对照 `references/blacklist.md` 的污染模式逐条检查（跨城同名小区、平台均值bug、中介话术、同小区分院价差异常等）。
3. **口径统一**：全部换算成含税总支出（用 `references/tax-calculator.md` 系数表）。
4. **产权判定**：用 `references/policy.md` 判定每套的产权类型与交易限制，标注验证状态（✅验证 / ⚠️存疑 / ❌证伪）。
5. **房龄核验**：快照中的"建成年代"多为**小区区间**（如 2012–2016、2009–2019 多期），逐套过滤时不能拿区间直接套 `age_max`——标注楼栋批次存疑，现场以房本"建成年份"栏为准。
6. **纠错五步法**（发现矛盾时强制执行）：逐字列出冲突点 → 针对性重搜 → 读原始页面/官方原文 → 验证口径（挂牌vs成交、含税vs裸价）→ 反转假设（主动找反例）。

### 第 5 步：统一输出

```
## 主清单（全部房源级验证，按含税价排序）
| # | 小区 | 验证房源（面积/户型/楼层/满X） | 挂牌 | 含税≈ | 产权/税费状态 | 证据URL | ✅⚠️ |

## 待核实区（有线索无房源证据）
## 证伪/高风险区（含证伪原因）
## 看房行动指引（小区地址、怎么去、现场必问三件事：房本附记页/契税票/业主净得价）
```

**输出纪律**：禁止宣称"穷尽/搞定"——结尾必须附"未覆盖项"清单（查无公开信息的空白点、只能线下核实的事项）。

## references/（按需读取）

- `tax-calculator.md` — 含税系数表与预算反推公式（第 4 步必读）
- `blacklist.md` — 数据污染模式、已证伪小区清单、高风险盘名单（第 4 步必读）
